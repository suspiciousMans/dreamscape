# Stream UIPIXELS (branch perf/uipixels, worktree /home/_l/dreamscape-perf/uipixels, CARGO_TARGET_DIR=/home/_l/dreamscape-perf/target-uipixels)
Goal: cut the egui shape / vertex / triangle count and tessellation time of every screen without changing a pixel. Biggest first: merge screen (10k shapes), loadout/deck builder (1.6k), booklet, store, HUD in play (hand cards, pixel icons, scanlines, tunnel overlay).
1. Build a measuring test first (`#[cfg(test)]` helper `ui_cost(mode) -> (shapes, vertices, triangles, tessellate_us)`) over every `hud::Mode` using the same fixtures as `screen_smoke` (look at `frame_with`/`overflows` helpers in main.rs tests; a booklet with ~239 cards via `cards::tests::record` loops is fine). Print a table; commit it as the baseline in NOTES.
2. Find where the shapes come from (`pixel_ui.rs`: `icon`, `panel`, `scanlines`, `split_text`, `glitch_text`; `booklet_ui::card`, `loadout_ui::draw_grid`, `hand.rs`, `pixels.rs` sprites). Typical wins, in order: (a) run-length merge horizontal runs of same-colour pixels into one rect (identical output), then merge vertically equal runs; (b) draw a whole sprite as ONE egui `Mesh` with per-pixel-run quads instead of separate `Shape::rect` (fewer shapes, same triangles); (c) cache static pixel art (icons, card frames, art by seed) as egui textures (`TextureOptions::NEAREST`) keyed by content, drawn as one textured quad: big win when the same sprite repeats (239 cards, 20 themes); (d) scanlines/grain/vignette as one textured or gradient quad instead of hundreds of rects; (e) avoid drawing off-screen/clipped cards of the scrolling grid (cull to the visible rows); (f) avoid re-allocating Strings/Vecs per frame in the painters (`format!` in hot loops).
3. Equality proof: for each change, a test that the OLD painter output and the NEW one cover the same pixels (rasterize the shapes/meshes of both into a small CPU pixel buffer and compare, or compare run-merged sets), tolerance 0. Keep `audit_text_fits_every_screen` and `screen_smoke` green.
4. Targets: merge screen < 3,000 shapes and < 20k triangles; loadout < 600 shapes; tessellate time down >= 50% on both; nothing else gets worse.
Own: pixel_ui.rs, pixels.rs usage, booklet_ui.rs, loadout_ui.rs, merge_ui.rs, deck_ui.rs, shop_ui.rs (drawing code only), engine/src/ui/backend.rs (egui), and hud.rs painters. Another stream (WORLDGL) owns the 3D render loop in main.rs/engine renderer; another (LOADSPIKES) owns load/update/build config.
