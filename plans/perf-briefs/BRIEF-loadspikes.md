# Stream LOADSPIKES (branch perf/loadspikes, worktree /home/_l/dreamscape-perf/loadspikes, CARGO_TARGET_DIR=/home/_l/dreamscape-perf/target-loadspikes)
Goal: remove frame spikes and cut CPU/alloc cost outside rendering, and make builds/tests faster. Code behaviour identical.
1. **Spikes**: the first seconds of a run and every dream transition show 25-36 ms worst frames. Add `perf::scope`s in `init`, `load_dream`, `dream::generate*`, `spawn_*`, texture/mesh upload, music start, and find the biggest. Fix what is simple and safe: avoid regenerating textures/meshes already built (cache by theme+seed), build big Vecs once with `with_capacity`, avoid `clone()` of large structs (Dream, booklet) on transitions, spread one-off work across frames only if order-independent. Pure generation functions (`dream::generate`) can be timed in tests across all themes/seeds: report ms per dream and make the slowest 3 faster (look for O(n^2) route/lair/placement searches and repeated `Vec::contains`).
2. **Per-frame CPU/alloc waste in `hud_view()`** (`rnd.hud_view` is 0.1 ms in play but 0.3-0.7 ms in menus: it clones every booklet card (`self.booklet.cards().cloned().collect()` for loadout/merge/deck, 239 cards, each with Strings and art specs) every frame). Make the view borrow or cache (rebuild only when the booklet, sort or mode changes: version counter), without changing what is drawn. Same hunt for other per-frame `String`/`Vec` building in `update()` and `hud_view()` (grep `format!`, `.to_string()`, `.clone()`, `collect()` inside per-frame fns). Add a test-only counting allocator (`#[global_allocator]` behind `cfg(test)` is awkward: instead count clones via a cheap helper or time the function over 1000 calls) and report ms/call before/after.
3. **Build and test time**: the full suite is 8-9 min, a release build ~6 min. Try, measuring each with `cargo test -p dreamscape --no-run` + the suite run time (the suite is long: time a representative slice, e.g. `-- dream:: deck:: screen_smoke`): (a) `[profile.dev] opt-level = 1` for the game crate and `[profile.dev.package."*"] opt-level = 3` for dependencies; (b) `[profile.test]` likewise; (c) `debug = "line-tables-only"`; (d) `incremental` settings; (e) splitting nothing (do NOT refactor main.rs). Keep `cargo build`/`test` behaviour correct; if a setting speeds the suite >25% and compiles in similar time, adopt it in the workspace `Cargo.toml` and note the numbers. (A cargo `.cargo/config.toml` with a faster linker is fine only if the linker (`mold`/`lld`) is already installed: check `which mold ld.lld`.)
4. Memory: note peak RSS of a run (`/usr/bin/time -v` or `/proc/<pid>/status` VmHWM; you have no display so use `cargo test` of dream generation) and any large retained structures you find; fix the obvious ones.
Own: load_dream and generation code, hud_view/update allocation fixes, Cargo profile settings. Do NOT touch the 3D render pass loop (WORLDGL) or UI painters (UIPIXELS).
