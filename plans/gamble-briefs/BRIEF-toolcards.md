# Stream TOOLCARDS (branch feat/tool-cards off feat/gamble-wave, worktree /home/_l/dreamscape-gamble/toolcards, CARGO_TARGET_DIR=/home/_l/dreamscape-gamble/target-toolcards)
Owner decision: in DECK runs the moth shop sells **tool cards** for run dust; a bought tool card is shuffled into the draw pile for the rest of the run (not saved in the booklet, gone when the run ends).
Why: deck runs refuse ability picks, so Bargain, Snare and the pick-only abilities (Tether, Veil, Pulse, Bind, Mirror, Quake, Surge, Haste and any other ability with no card source: derive it as `ALL_ABILITIES` minus every ability some card can teach via `powers::power_of`/`PAIR_ABILITIES`) are unreachable there.
Tasks:
1. `deck.rs`: run-only cards. The deck holds booklet numbers; add a reserved number range for tool cards (`TOOL_BASE`, e.g. `u32::MAX - 64`, one id per ability: `tool_id(ability)` / `tool_ability(id)`), pure helpers + tests. A tool card is never saved: `lore.deck`, the booklet and `Booklet::card(n)` never see it. `Deck::insert_shuffled(id, seed)` puts it into the draw pile at a seeded random position (own stream `dream_seed ^ 0x700C_A4D5 ^ n`); never loses/duplicates cards (extend the property test). A resumed run (saved run state) must keep its tool cards: add `#[serde(default)] tool_cards: Vec<u32>` to the saved run, and rebuild them into the deck on resume (the old rule says a resumed run falls back to the fixed loadout: keep that, but save the list so nothing paid for is lost, and tell the player in the NOTES what happens).
2. Rendering: a tool card has no booklet `Card`. Give `hand.rs`/`hand_view` a synthetic face: the ability's icon/tint/name, a plain "TOOL" tag (use a distinct frame colour), key label, cooldown charge like any card. It gives NO passive/edge/dream. Use the existing `HandCard.card: Option<Card>` = None path if it exists, else add a small enum. Animations (draw/flick/riffle) must work unchanged.
3. Shop: in deck runs the moth shelf (`moth_shop::stock`) offers up to 2 tool cards (in place of the ability candidates that fixed runs get; fixed runs unchanged), priced by strength (`TOOL_PRICE_*` consts: cheap utility 8, mid 14, strong 22), rising +4 dust for each tool card already bought this run, at most `MAX_TOOL_CARDS = 2` held in the deck at once (a third shows "no room"). Bought card shows in the hand animation (a bought card flies into the stack with the riffle). Odds/prices are plain text on the card. Sold by dust only (`bonus_dust`).
4. Wire in `use_ability` etc.: using a tool card discards it like any other card; it is shuffled back (it stays in the deck for the run).
5. Tests: id mapping both ways, range never collides with booklet numbers (`debug_assert` booklet numbers < TOOL_BASE; test with the booklet's max), insert keeps counts, shop offers tool cards only in deck runs, price rise, cap, save/resume keeps them, hand view of a tool card, `audit_text_fits_every_screen` and `screen_smoke` green.
Own: deck.rs, hand.rs/hand_view additions, moth_shop.rs deck-run stock, `// === toolcards ===` blocks. Final reply 5 lines. NOTES: plans/gamble-briefs/NOTES-toolcards.md (list the new player-facing text for owner approval).
